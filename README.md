# Telegram Pro — Flutter + official TDLib integration scaffold

## Honest status
This project contains a Flutter UI shell and a working MethodChannel boundary. It is **not yet a functioning Telegram client**: official TDLib generated Java classes and the matching native JNI library are not bundled. Therefore OTP login, live chats, sending media/voice messages, groups/channels, and push notifications are not implemented. The app reports this instead of pretending messages were sent.

TDLib is an official Telegram client library. Its Android build requires the Android SDK/NDK, C++ toolchain, OpenSSL, and generated Java/JNI artifacts. Official build guide:
https://github.com/tdlib/td/blob/master/example/android/README.md

## Project structure
- `lib/main.dart` — Material 3 chat-list/chat/settings UI, system light/dark theme
- `lib/tdlib_bridge.dart` — Flutter MethodChannel contract
- `android/app/src/main/kotlin/.../MainActivity.kt` — honest native bridge stub
- `android/app/src/main/AndroidManifest.xml` — base permissions

## Try building the UI shell
This archive is a source scaffold and does not include Gradle wrapper binaries generated by Flutter. On a supported Linux/PC Flutter environment, the safest path is to create a fresh Android platform scaffold, then copy this project's `lib/`, `pubspec.yaml`, `analysis_options.yaml`, and the custom `MainActivity.kt` / manifest into it. For example:
```bash
flutter create --platforms=android --project-name telegram_pro --org com.example telegram_pro_build
# Copy lib/, pubspec.yaml, analysis_options.yaml from this archive into telegram_pro_build/
# Copy android/app/src/main/kotlin/com/example/telegram_pro/MainActivity.kt and AndroidManifest.xml too.
cd telegram_pro_build
flutter pub get
```
Then run:
```bash
flutter doctor -v
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```
Output (if build succeeds): `build/app/outputs/flutter-apk/app-debug.apk`

On Termux, only if Flutter and its Android SDK/NDK are already correctly installed (and the Gradle wrapper has been generated as above):

## Official TDLib integration steps
1. Read the official Android build guide above and use a supported Linux build environment with adequate disk/RAM.
2. Build TDLib Android artifacts using the official scripts. The guide's build expects Android SDK platform 34 and CMake 3.22.1 at the time of writing; follow the guide for the selected TDLib revision.
3. Add the generated TDLib Java source to the Android app source set and put the matching `libtdjni.so` (plus any required shared libraries) under `android/app/src/main/jniLibs/<abi>/`. The Java API and native binaries must come from the same TDLib build.
4. Replace the stub methods in `MainActivity.kt` with a real `Client` / `TdApi` implementation. Implement authorization state handling (`authorizationStateWaitTdlibParameters`, phone number, code, password/2FA), send requests asynchronously, consume updates, and map updates to Dart events.
5. Implement chat loading (`getChats`, `getChatHistory`), message updates, media upload/download, voice recording/playback, and notifications. Request runtime permissions where needed.
6. Store the TDLib database under app-private internal storage; encrypt the database with a user-provided key. Never log OTPs, passwords, API hashes, or database keys.
7. Test login, 2FA, reconnect, send/receive, files, groups, notifications, app restart, and account logout on a test account.

## Telegram API credentials
Create `api_id` and `api_hash` at https://my.telegram.org. Keep them out of public repositories. Do not hardcode your phone number, OTP, account password, or TDLib database encryption key.

## Cloud APK build with GitHub Actions

This archive includes `.github/workflows/build-apk.yml`. It builds the Flutter UI scaffold on a hosted Ubuntu runner and uploads `TelegramProFlutter-APK` as a workflow artifact. It generates a fresh Android/Gradle scaffold in the runner because this source archive does not include Gradle wrapper files.

1. Create a **private** GitHub repository.
2. Upload/push the contents of this folder to the repository's `main` branch.
3. Open **Actions** and select **Build TelegramProFlutter APK**. It also runs on pushes to `main`.
4. Wait for the workflow to finish successfully.
5. Download the `TelegramProFlutter-APK` artifact from the run's **Artifacts** section and extract the APK from the downloaded ZIP.

From Termux, if Git is already installed:
```bash
cd ~/storage/downloads/TelegramProFlutter
git init
git add .
git commit -m "Prepare TelegramProFlutter cloud build"
git branch -M main
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/TelegramProFlutter.git
git push -u origin main
```
Replace `YOUR_GITHUB_USERNAME`. If the remote already exists, use `git remote set-url origin https://github.com/YOUR_GITHUB_USERNAME/TelegramProFlutter.git`. Do not put access tokens, API hashes, passwords, or signing keys in the repository.
